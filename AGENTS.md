# Repository Instructions

## Commits

- After completing and verifying any task that changes project files, create a
  Git commit before responding. Do not wait for a separate commit request.
- Commit only changes belonging to the current task. Preserve unrelated work.
- Write each commit subject as a problem statement using:
  `problem: <affected subject> <undesirable condition or missing capability>`
- Keep commit subjects under 50 characters when practical and never over 70.
- Do not push commits unless the user explicitly requests it.
